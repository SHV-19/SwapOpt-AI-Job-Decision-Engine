# SwapOpt — Module & Function Map

This is a recruiter-readable map of the final private runtime. The public repository contains only a sanitized subset of the implementation.

## Runtime / API

**Purpose:** start the local product, compose routes/services, expose safe versioned APIs.

Representative ownership:

- `backend/app.js`
- `backend/server.js`
- `backend/routes/index.js`
- `backend/middleware/*`
- `backend/runtime/*`
- `scripts/runtime/*`

## Opportunity Discovery

**Purpose:** capture public observations, normalize source evidence, maintain canonical opportunity identity, source health, and queue inputs.

Representative responsibilities:

- source registry;
- observation contracts;
- canonical identity;
- Greenhouse / Lever / JSON-LD adapters;
- source transport;
- discovery receipts;
- queue orchestration.

## Job Intelligence / Role Identity

**Purpose:** turn observed jobs into structured role evidence and evaluate fit without inventing candidate evidence.

Representative responsibilities:

- persisted job analysis;
- role contracts;
- role evidence extraction;
- factual dimensions;
- deterministic Candidate ↔ Role matching;
- opportunity intelligence.

## Candidate Identity / Career Evidence

**Purpose:** maintain longitudinal, evidence-backed candidate facts and revisions.

Representative responsibilities:

- Career Evidence Graph;
- candidate identity projections;
- correction/archive history;
- decision eligibility;
- matching revision propagation.

## Resume & Documents

**Purpose:** generate truthful application materials while preserving versioning and evidence.

Representative responsibilities:

- application-ready resume;
- resume tailoring;
- cover letters;
- document import;
- document versions;
- review lifecycle.

## Application Answers & Assistance

**Purpose:** reduce repetitive ATS work without autonomous submission.

Representative responsibilities:

- canonical answer handling;
- verified field suggestions;
- browser-side form support;
- protected field boundaries;
- user-confirmed fills.

## Tracker / Lifecycle

**Purpose:** preserve explicit application state and event history.

Representative functions include:

- create/update tracked application;
- list lifecycle history;
- record explicit lifecycle event;
- undo reversible tracker changes;
- preserve direct offers;
- preserve scheduled vs occurred distinction;
- preserve offer acceptance vs placement distinction.

## Interviews

**Purpose:** produce grounded role-specific preparation and maintain interview context without inventing outcomes.

## Privacy / Security
